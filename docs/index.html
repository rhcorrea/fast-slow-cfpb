fast-slow-cfpb

This project tests whether Laya, a small local decision model, can serve as a platform component: something you point at a new problem and get a fast, honest answer from. The test problem is sorting CFPB consumer complaints into ten products. Laya labels each complaint in about a tenth of a second and reports how sure it is; when it is unsure, the complaint goes to GPT-5.6 Sol, which is more accurate but about 20 times slower and billed per call. Qwen3.5-4B, a general local model, and a plain TF-IDF classifier serve as baselines.

Verdict so far: Laya works as a fast decision component. Zero-shot, its confidence is good enough to route on: sending its least sure 27.5% of complaints to Sol keeps 98.5% of Sol's accuracy on real traffic. Its weak point is zero-shot accuracy on a new taxonomy, 48.0% on the balanced test set against 66.1% for Qwen3.5-4B. It learns quickly from labels: fully fine-tuned on a GPU, it reaches 68.5% with 50 labelled complaints per class, where TF-IDF trained on the same complaints gets 60.6%, and 73.6% with 500, level with TF-IDF's 73.2%. Fine-tuned, its confidence stays calibrated, as long as you read answer_confidence rather than the field named confidence. A second question can be added without hurting the first. Scorecard below.

The routing signal

Laya's confidence ranks its own answers well

Laya's accuracy within each band of its answer probability, validation set; the dark tick marks the band's mean probability. Accuracy rises from about 20% in the two lowest bands to 74% in the highest, so the score ranks answers well. Zero-shot it claims more than it earns, most at the top: complaints scored 0.9 or more average 0.96 and are right 74% of the time. On the real class mix, where its strongest classes dominate, its calibration error is 0.07 on validation and 0.09 on test.

Local models

Put first, Qwen3.5-4B needs Sol for 16% of complaints, against Laya's 28%

Qwen3.5-4B, 4-bit, running on MLX on this Mac (M4, 16 GB). The prompt numbers the ten classes and one forward pass reads the probabilities of the ten digit tokens, so it returns a label and a confidence like Laya does. It ran over all 4,000 validation and test complaints at a median 1.29 s each, peaking at 3.9 GB; running the shared instructions once and reusing them cut that to 0.78 s. Laya's README calls it a base to fine-tune, and that shows: zero-shot, a general 4B model beats it by 5 points on the real mix and 18 on the balanced set.

Supervised baseline

Training on labelled complaints beats every model here, Sol included

The project holds back 3.85M labelled narratives that no model had learned from. src/models/tfidf.py trains TF-IDF word and word-pair features with logistic regression on up to 30,000 per class (278,594 complaints), in about 6 minutes on the CPU. Training size and regularization were picked on validation only, from 8,000 or 30,000 per class and C of 1, 3, 10 or 30. It trains on equal classes, so it ships two ways: tfidf reweights its probabilities to the real class shares, for routing real traffic, and tfidf-balanced doesn't.

The router's usual rule, the lowest threshold reaching 97% of Sol's accuracy, picks 0 for TF-IDF because it already beats Sol on validation, so it would never ask Sol. Its 0.61 is the threshold that maximizes validation real-mix accuracy instead. Times are live, one complaint at a time; scoring a whole set at once takes about 0.1 ms per complaint. Without reweighting, TF-IDF also gets debt or credit management right 55.5% of the time on the test set, against 35.0% for Sol and 27.5% for Laya: it learns how CFPB actually files that class.

Fine-tuning

Fully fine-tuned, Laya leads with few labels and keeps pace with many

Laya fine-tuned with its own trainer on 10 to 500 labelled complaints per class, against TF-IDF trained on exactly the same complaints. Two setups: on this Mac only the top 8 of 28 layers could be trained; on a Colab T4 GPU every layer was, in mixed precision. A new problem usually starts with few labels, so the left side of this chart matters most for a platform.

Test set · balanced accuracy
Laya, every layer fine-tuned on a T4, soft-ce loss (left: zero-shot); ring: Laya's default rlcd loss Laya, top 8 layers fine-tuned on this Mac (dashed) TF-IDF on the same complaints, mean of 5 samples; whiskers span them

Mac: one run per size, top 8 of 28 encoder layers trained, 10, 4, 3 and 1 epochs from smallest to largest, 16 to 60 minutes each. T4: one run per size, every layer, fp16, 4 epochs, 4.6 minutes at 50 per class and 45 at 500. A one-epoch T4 run at 500 scores 71.7%, against the Mac's 60.2% with the same single epoch, so the gap comes from the frozen layers, not from training longer. Zero-shot scores 48.0% on both machines. TF-IDF's five samples spread over about 4 points at 10 and at 50 per class, so Laya's 12-point lead at 10 (on the Mac) and 8-point lead at 50 (on the T4) both hold.

On the real class mix, training on equal classes erases what Laya knew about which products are common: scored as is, the T4 model at 50 per class drops to 65.6%, below zero-shot's 78.2%. Shifting its probabilities to the real class shares, as the tfidf model does, more than recovers it: 83.5% at 50 per class and 86.8% at 500 with the default loss, against TF-IDF's 66.4% and 84.0% shifted the same way. The Mac runs reach 78–79% shifted.

What it took to train on a 16 GB Mac

The first three runs ran out of memory. Each was stopped by a GPU memory cap set in advance rather than hanging the Mac.

  • Full fine-tuning doesn't fit. All 421M parameters in fp32 need about 6.4 GB for weights, gradients and optimizer state before any complaint goes through. Freezing all but the top 8 layers cut that to about 3 GB.
  • Variable batch shapes leak memory. PyTorch's Apple GPU backend keeps work per input shape, and Laya pads each batch to its own longest complaint, so memory outside the tensors kept growing. Padding to multiples of 128 tokens and releasing the cache every 25 batches held it flat.
  • The freezing caused the plateau. A full fine-tune in mixed precision on a free Colab T4 needed none of these workarounds and scored 9–13 points higher at 50 and at 500 per class.

Review

What's solid and what needs attention

Needs attention

  • High
    The OpenAI account is out of credits

    The last live call to Sol returned "no credits remaining", so nothing that escalates to Sol works, whichever model goes first. Every Sol figure on this page comes from answers saved earlier.

  • Medium
    Only one problem type has been tested

    Everything here is single-label text classification on one data set. Showing Laya works across problem types needs a second, different use case, for example one with yes/no or score questions.

  • Medium
    No router with fine-tuned Laya first yet

    The T4 predictions are in data/processed/t4/results and scored on the real mix, but no threshold has been picked or router evaluated with fully fine-tuned Laya in front of Sol.

  • Low
    Debt or credit management is still the weakest class

    The zero-shot models get it right a third of the time or less, because the class overlaps credit reporting. Supervised TF-IDF without reweighting reaches 55.5% on the test set, but the real-mix reweighting the router uses drops it to 15.5%, since the class is 0.2% of real traffic.

  • Low
    Each question costs a full pass

    Laya doesn't share one reading of the complaint across questions, so a schema with many fields costs proportionally more. Worth checking whether its batching options can pack questions together before relying on wide schemas.

  • Low
    Saved Qwen predictions predate its speed-up

    Reading the shared instructions once rounds slightly differently: on 200 complaints the median probability moved 0.002 and no routing decision changed. A full rerun, about 52 minutes, would make saved and live results identical.

Working well

  • Solid
    Fully fine-tuned, Laya matches TF-IDF

    Trained on every layer on a T4, it scores 68.5% at 50 per class, 8 points ahead of TF-IDF on the same complaints, and 73.6% at 500, level with TF-IDF's 73.2%. Zero-shot matched the Mac exactly, 48.0%, so the two machines agree where they should.

  • Solid
    Routing reads Laya's calibrated confidence

    system1.classify returns answer_confidence, the saved predictions carry the same score, rebuilt from their stored probabilities, and tests/test_eval.py checks which field is read.

  • Solid
    Laya learns from 10 examples per class

    100 labelled complaints and 16 minutes of training lift it 10 points, 12 ahead of TF-IDF on the same complaints, and a second question can be trained alongside without hurting the first.

  • Solid
    A free model now beats Sol on real traffic

    Supervised TF-IDF scores 90.6% on the real-mix test set by itself, against Sol's 89.4%, and 92.4% when its least sure 9.1% go to Sol. Settings were picked on validation only, and tests/test_tfidf.py checks the real-mix reweighting.

  • Solid
    Qwen runs 1.8× faster

    slm.py runs the 242-token instructions once and gives each complaint a copy of that state, so Qwen takes 0.78 s instead of 1.41 s. tests/test_slm.py checks that the split prompt reads exactly like the full one.

  • Solid
    Reproducible data pipeline

    Download is idempotent, and preprocessing streams the zips without unpacking 5 GB of CSVs to disk.

  • Solid
    Every Sol answer is a valid label

    Structured outputs constrain the reply to the ten classes. All 4,000 responses parsed.

  • Solid
    Router and evaluation are in the codebase

    src/router.py routes saved predictions or live complaints. src/eval.py picks the threshold on validation, reports test once in both class mixes, and writes a full sweep to eval.json. --fast and --slow swap either side, and the router runs Laya, TF-IDF or Qwen first live. tests/test_eval.py checks the metric math.

  • Solid
    The router keeps 98.5% of Sol's accuracy

    On real-mix test data at 0.55 it sends 27.5% of complaints to Sol and reaches 88.1%. A perfect router would send 21.8% and reach 92.3%, so a better confidence score still has room to help.

  • Solid
    Sol runs resume and run in parallel

    system2.py runs 8 calls at once, logs each answer as it arrives, and reuses any complaint already answered. The redraw only paid for the complaints that were new.

  • Solid
    Every class is tested across all naming eras

    The split was redrawn after the sub-product relabel and both systems rerun, so no class is tested only on recent complaints.

  • Solid
    Local models run without taking the Mac down

    The first run hung the machine as MLX's buffer cache grew. slm.py now caps the cache and stops the run above 8 GB, and the full 4,000-complaint run peaked at 3.9 GB. Model weights live on the SSD under models/.

Suggested order

  1. Add OpenAI credits.
  2. Pick a threshold and route with fully fine-tuned Laya first, from the T4 predictions.
  3. Try Laya on a second, different problem type.
